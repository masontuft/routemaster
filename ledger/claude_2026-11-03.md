One route per day, rebuilt in a transaction, stops stored by reference. The day board books only Requested jobs, one status change each. Mason approved each segment in turn.

The dashboard and docs name `docs/architecture/RouteMaster-Database-Schema.md`, which was untracked before this session and was left alone. Verified: `pnpm lint` clean, `pnpm test` 386 of 386 against `TEST_DATABASE_URL`. ADR 0013 is Proposed until a real-address trial. ## Seeded test database

- **Changed:** `src/db/seedTestData.js`, `scripts/seed-test-data.js`, `package.json` (`seed:test`), `src/seedTestData.test.js`, `docs/setup/local-development.md`, `CHANGELOG.md`, this file. Branch `feat/test-seed-data`, off `main` after the route builder merged.
- **Why:** `routemaster_test` existed but was empty; tests use throwaway per-file schemas. Mason wanted seeded data to run the app against by hand.
- **Decisions:** Seed goes through the app's own models (`DayBoard.scheduleMany`, `Staff.changeStatus`, `RoutePlan.replaceForDay`) so history rows and transition rules are real. Marker customer email makes it idempotent; not transactional, so `--reset` is the recovery. Fixed coordinates, no geocoding calls. Dates relative to today. Only `getTestDatabaseUrl()` is used, so `--reset` cannot reach `DATABASE_URL`.
- **Open / next:** Seeded route is about 0.8 miles total because the invented points are close together. Not run in CI (CI tests call the module on a throwaway schema, not the script). Fictional city "Riverbend", not tied to `SERVICE_STATE`.
