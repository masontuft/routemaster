## Messenger handoff: decisions and ADR 0015

- **Changed:** `docs/adr/0015-messenger-handoff-api.md` (new), `docs/adr/README.md`, `docs/integrations/sprinkler-messenger.md`, `docs/product/roadmap.md`, this file. Branch `feat/messenger-handoff-api`, branched from `main` after PR #57 (rebooking) merged, so the next migration is 024.
- **Why:** Mason asked to set up the Sprinkler Messenger deep-link integration. Three read-only agents mapped both repos first. Mason answered: host `https://routemaster-8w24.onrender.com`, Routemaster is the source of truth for "texted" (the sheet is being phased out), consent and opt-out go on the roadmap, and Routemaster is built first and tested with curl.
- **Decisions:** Opaque batch token, no names, phones or links in the URL. A second fetch re-mints links and skips anyone marked sent, instead of the spec's earlier 409, so a dropped connection is recoverable. Fetch window 1 hour, results window 24 hours, since a tap per message takes longer than an hour. Magic links are minted at fetch, not at staging. Custom scheme first, universal links later. The agent-suggested `/handoff?t=` path was dropped in favor of the spec's `batch/<token>`.
- **Open / next:** Nothing is built yet and nothing is committed. Next segment: migration 024 (`messenger_batches`, `messenger_batch_recipients`), model, the two endpoints, tests, `docs/api/endpoints.md` and threat model. Then a staff page to stage a batch. Messenger needs a `batch/[token]` route and per-recipient bodies (its queue sends one shared template). Open spec questions 4, 5 and 7 remain.
