## Staff invitation email flow

- **Changed:** Added `/admin/users/invite` to create pending owner or dispatcher accounts and send a seven-day setup link using `INVITE_RESEND_API_KEY`; added rate-limited `/staff-invite/:token` setup routes; added resend controls on `/admin/users`; kept direct temporary-password creation; used domain-separated signed tokens with single acceptance through the pending password state. Reused a shared email action URL builder for password resets. Updated email configuration, process, threat model, roadmap, handoff and changelog docs.
- **Why:** Mason asked about staff invitation emails after password-reset sending was working. The key existed in Render but the app did not read it.
- **Decisions:** No migration: pending staff are represented by `password_hash IS NULL`, which is supported by migration 011. The invitation is bound to user id, email and role, expires after seven days, and becomes invalid after password setup. Resend is available while pending; already-sent links remain valid until their expiry or first acceptance. Existing temporary-password creation remains available.
