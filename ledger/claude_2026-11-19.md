## Companies, 3c: change your own password

- **Changed:** new `src/controllers/account.js`, `src/routes/account.js` (wired in `src/app.js`), `src/views/account/password.ejs`, `validatePasswordChange` in `src/utils/validation.js`, and `findById`, `setPasswordHash` and `endOtherSessions` in `src/models/user.js`. The account menu in the header has a Change Password link for users who have an email. Test: `src/account.test.js` (8). Docs: the roadmap (the item becomes "Forgot password"), the handoff, the process doc (a Changes row), `CHANGELOG.md`. Branch `feat/company-password-change`, on top of 3b.
- **Why:** Mason asked for it at the end of the company work: an owner made by `pnpm company:create` otherwise keeps the password it was given.
- **Decisions:** (1) The page needs the current password, so a stolen logged-in session cannot set a new one. (2) After a change the session id is regenerated and every other session of that user is deleted from the sessions table, matched on the user id inside the session data. Other users' sessions, in any company, are not touched. (3) The new password follows registration (8 characters, 72 bytes) and must differ from the current one. (4) The POST uses the same per-address limiter as login, so guessing the current password is limited; the cost is that the limit is shared with logins from that address. (5) A user with no password (a customer who signs in by link) gets a 404 and no menu link.
- **Open / next:** Forgot password has no way back, since nothing sends email; it is the roadmap item now. A password change does not log a record. Verified: `pnpm lint`; `src/account.test.js` (8 of 8); mutation check (ending other users' sessions instead of the user's own makes two tests fail); the full suite is run before the commit.

- **Why:** Mason wanted to change the emails of the seeded Tuft accounts from the app, not SQL.
- **Decisions:** (1) Own email needs the current password and the new email typed twice, since nothing can confirm the new address. (2) An owner changes only users of their own company, only ones with a password, and not themselves, without asking for that user's password; the user keeps their password and there is no reset, so an email alone cannot take an account over. (3) An email that exists in any company is refused with one plain message, which tells an owner that an address is in use somewhere.
- **Open / next:** There is no record of who changed an email. Other sessions are not ended by an email change. Verified: `pnpm lint`; `src/email.test.js` (8 of 8); mutation checks (no company filter, no password check: each fails a test); the full suite is run before the commit.
