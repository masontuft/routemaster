## Companies, pass 2a: the session carries the company, customers and properties are scoped

- **Changed:** new `src/config/company.js` (`DEFAULT_COMPANY_ID = 1`), `src/utils/company.js` (`companyOf(req)`), `src/middleware/ensureCompany.js` (wired in `src/app.js` after the CSRF check and before `res.locals.user`). `src/models/customer.js` (every function that reads or writes customers takes `companyId` after `pool`; the bulk `countClear` and `clear` filter all seven counts and both deletes by company), `src/models/property.js` (`findById`, `update`, `listByNormalizedAddresses` filter through the customer), `src/models/user.js` (`create` takes `companyId`, `findByEmail` returns it), `src/models/staff.js` (`matchAsNew` makes the customer in the request's company). Controllers: `auth.js`, `link.js`, `schedule.js`, `staff.js`, `clear.js`, `import.js`, `admin.js` (`createUser`). `src/import/matching.js`. Scripts and `src/db/seedTestData.js` pass company 1. About 30 existing test files were rewritten to pass company 1 (a script that changed only the listed functions), plus new `src/companyIsolation.test.js` and `src/middleware/ensureCompany.test.js`, ADR 0018, `CHANGELOG.md`. Branch `feat/company-scoped-models`, off `main` after PR #74.
- **Why:** Mason approved the pass-one plan (2026-11-19). It is the first step where the company changes what a query returns.
- **Decisions:** (1) `companyId` is an explicit argument, so a forgotten one is `NULL`: a read finds nothing and an insert is refused. (2) The company comes from the session, set at login, register and link redeem; `companyOf(req)` throws when it is missing and never falls back to company 1. (3) `ensureCompany` fills a missing `companyId` from the `users` row so sessions open before this deploy are not logged out; a user whose row is gone gets none. (4) Public `/register` and `/schedule` use `DEFAULT_COMPANY_ID`, named in code and not left to the column default. (5) A property has no company of its own, so its three entry points filter through the customer. (6) `matchAsNew` takes the company from the locked request row, not from the staff user. (7) `revokeLink` now checks the customer is in the company first. (8) The table lock in `Customer.clear` is still table-wide, so two companies' bulk deletes wait for each other.
- **Open / next (named gaps, not done):** `Staff.matchToProperty` reads the form's property id unscoped (2b). `updateProperty` checks the area with an unscoped `Area.find` (2c).
